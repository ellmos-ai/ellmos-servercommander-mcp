[POSITIONING & VALUE PROPOSITION]
ellmos ServerCommander MCP is an authoritative, local-first Model Context Protocol (MCP) server
specialized in resilient, diagnostic, and dry-run-first server operations. Designed specifically
for AI coding assistants and autonomous agent platforms (Claude Code, Cursor, Codex, Antigravity,
Gemini), it bridges AI agents with system administration tasks without exposing production
infrastructure to unverified, destructive mutations.

Key Differentiators:
1. Dry-Run & Staging First: Deployment planning (`sc_deploy`) calculates complete SHA-256 tree
   digests and verifies target profiles locally before executing any remote commands.
2. 100% Local-First & Zero-Egress: All diagnostics, forensic log parsing, and manifest hashing
   run strictly locally; zero cloud dependencies, zero hidden telemetry.
3. Resilient Forensic Log Analysis: In-memory and streaming Apache/Nginx access log analysis
   identifies error spikes, bot scanners, and suspicious path traversals with optional structured
   JSON export.
4. Non-Blocking Health Probes: Asynchronous HTTP endpoint verification executes within dedicated
   worker threads with resilient batch failure handling.
5. Multilingual Native i18n Engine: Full support for 6 locales (en, de, es, zh, ja, ru) across
   all MCP tool declarations, parameter schemas, and diagnostic outputs.

[TARGET PERSONAS]
1. Autonomous AI Agent Engineers & Tooling Architects:
   - Need reliable server diagnostics and deployment preflight checks without exposing raw bash shells.
   - Require standardized JSON-RPC schemas and structured outputs for tool-calling agents.
2. DevOps Engineers & Site Reliability Engineers (SREs):
   - Seek deterministic release verification, SHA-256 tree hashing, and local deployment histories.
   - Demand safe dry-run manifests and symlink traversal safeguards before remote sync.
3. Security-Conscious System Administrators:
   - Require unprivileged (RunAsInvoker) execution, zero sudo/root requirements, and strict secret isolation.
   - Want instant local forensic analysis of web server access logs during incident triage.
4. Solo Developers & Full-Stack Maintainers:
   - Need a lightweight, zero-configuration MCP server to monitor API health and server configurations
     directly from their IDE or AI chat interface.

[GOVERNANCE & RUNTIME INVARIANTS]
- INV-LOCAL-01: 100% Local-First & Zero-Egress (Local diagnostic and dry-run execution; zero unverified outbound telemetry)
- INV-DRY-02:   Fail-Safe Deployment Staging (Default `dry_run=True`; manifest calculation & SHA-256 tree hashing before target execution)
- INV-LOG-03:   Sanitized Access-Log Analysis (Read-only parse; regex token extraction; optional structured JSON output without credential leaks)
- INV-PROBE-04: Non-Blocking Resilient Health Probes (Worker thread HTTP GET with strict timeouts; resilient error handling without aborting batches)
- INV-MAIL-05:  Dry-Run Mail Configuration Status (Readiness checks report gaps without sending emails; protocol verification only)
- INV-PRIV-06:  Non-Elevation / RunAsInvoker (Unprivileged user mode; zero sudo/root/UAC requirements)
- INV-SEC-07:   Safe Process & Working Directory Isolation (`PYTHONSAFEPATH=1`; hardened launcher against rogue working directory packages)
- INV-I18N-08:  Native Multi-Language i18n Engine (6 locales: en, de, es, zh, ja, ru with automated English fallback)
- INV-SYNC-09:  Cloud-Sync & Multi-Agent Lock Hardening (.gitignore hardened against sync conflicts `*-conflict-*` and multi-agent locks `LOCK*`)
- INV-SLA-10:   48-Hour Response & 5-Day Triage SLA (Direct security response via security@ellmos.ai and security@open-bricks.org)
